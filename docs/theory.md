# Теоретична основа реалізації

## Синтаксис
Синтаксис SIPL задається БНФ, тобто породжуючою контекстно-вільною граматикою. Слово належить
мові, якщо для нього існує виведення з `<програма>`. Виведення зображується деревом синтаксичного
виводу: у внутрішніх вузлах категорії (`<оператор>`, `<вираз>`, ...), у листках термінали. Якщо
прочитати листки зліва направо, отримаємо початкову програму - це перевірка синтаксичної
правильності (`sipl tree --check`). AST відрізняється від дерева виводу тим, що не містить
службових терміналів (`:=`, `;`, `begin`, ...) і зберігає лише структуру.

## Семантика
Програма задає функцію над станами. Стан - набір пар «змінна - значення» (номінативні дані).
Програмна алгебра `A_SIPL` має композиції:

| Композиція | Формула | Правило в коді |
|---|---|---|
| суперпозиція | `S^n(f, g1..gn)(st) = f(g1(st), ..., gn(st))` | `AF_S` (виклик `value`) |
| присвоювання | `AS_x(f)(st) = st∇[x ↦ f(st)]` | `AF_AS` |
| послідовне виконання | `f1 · f2 (st) = f2(f1(st))` | `AF_SEQ` |
| розгалуження | `IF(fb, f1, f2)(st)` = `f1(st)` якщо `fb(st)=true`, інакше `f2(st)` | `AF_IF` |
| цикл | `WH(fb, f)(st) = st_n`, де `st_0 = st`, `st_{i+1} = f(st_i)`, `fb(st_i)=true` для `i<n`, `fb(st_n)=false` | `AF_WH` |
| розіменування | `x⇒(st) = st(x)` | `AF_DNM` |
| тотожна | `id(st) = st` | `AF_ID` |

Семантичний терм програми будується рекурсивно за структурою синтаксису правилами
`sem_P`, `sem_S`, `sem_A`, `sem_B` (`semantics.py`, імена правил `NS_*` як у практикумі).
Застосування терму до стану - це «тестування» програми (`evaluator.py`).

Функція може бути не визначена на стані (⊥): значення змінної немає в стані, або цикл не
завершується. Для нескінченних циклів перевіряється ліміт кроків, після якого результат
вважається невизначеним.

## Коректність програм
Часткова коректність: якщо програма завершилась, результат правильний. Повна коректність:
програма завершується і результат правильний. Для циклів доводиться індуктивне твердження про
стан після `k` ітерацій (практична робота 3). Автоматичне доведення в цьому проєкті не
реалізовано (завдання SEM-04 не обрано), інструмент лише обчислює терм на конкретних станах.

## Що перевіряють тести
Інтерпретатор і семантичний терм реалізовано незалежно (AST виконується напряму, а терм
обчислюється за формулами `AF_*`). Тест `test_term_agrees_with_interpreter` порівнює їх на всіх
прикладах - це перевірка того, що побудова терму зберігає семантику програми.
